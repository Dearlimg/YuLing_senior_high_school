## 产品与技术基线

本项目是独立 Web 服务，桌面端与手机浏览器均为正式使用场景，不依赖微信登录、公众号、微信 SDK 或小程序容器。PRD 中的业务规则继续适用，微信专属表述不作为实现约束。

复用现有 Go 1.26 / Gin / GORM / MySQL / Redis，保持 `controller → logic → dao → model`。前端采用原生 ES modules、CSS 与语义化 HTML，由 Go embed 打包并同源提供，现有 Docker、交叉编译和 Gitea CI 无需新增 Node 构建步骤。前端 API 单独封装，便于后续替换框架。

视觉基线：纸白背景、酒红品牌色、暖金细节，中文衬线标题、校园摄影、克制动效。优先形成完整页面，再完成数据闭环。校园图片注明来源；演示人物与帖子必须明确标注为虚构，禁止混入生产数据。

## 默认业务决策

- 校友身份认证机制未定：所有普通访问者均看不到手机号、微信、邮箱，不将登记等同于认证。
- 编辑码与删除码采用安全随机数，创建成功仅展示一次；不进 URL、浏览器持久缓存或日志。
- 在读同学单独保存理想大学；转为校友必须明确修改身份与实际院校。
- P0 校友卡为 Web 卡片。头像为姓名首字与五种颜色，无人物头像上传。
- 公开内容先发后审，界面明确提示；提供管理员下架、恢复与审计 API。复杂审核台、验证码服务接入与身份认证为上线前运营决策项。
- 图片以压缩后的二进制持久化在 MySQL，复用现有基础设施，避免只读容器本地上传丢失；规模增大后迁移对象存储。
- 本地演示模式仅限非生产环境，数据保存在进程内，重启即重置；生产始终使用 MySQL/Redis，禁止自动回退到演示数据。
