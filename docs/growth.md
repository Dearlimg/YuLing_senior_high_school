# 领卡与同班传播（2026-11-13）

## 已实现的 P0

- `/register` 首步仅收身份、姓名、届别、班级。在读生班级必填，校友班级选填；默认头像为榆红。无需账号密码。大学、城市、单位、联系方式与寄语在领卡后补充。
- 成功页在本次页面会话内显示编辑码，并提供复制、邀请同班、保存校友卡海报、补充近况和可选绑定账号。编辑码仅保存在模块内存，刷新后清除；用户需自行保存。
- 未绑定账号者从自己的公开卡片进入“管理我的校友卡”，凭编辑码修改。绑定账号沿用既有事务与唯一约束，不再创建第二张卡，绑定后编辑码失效。已有账号继续使用个人中心。
- 手机号与微信的未来可见意愿分别选择，默认均为 false；邮箱不公开。尚无校友认证，所有普通访客仍看不到联系方式。旧 `contact_public` 继续兼容旧接口，新的逐项选项需要本人明确选择。
- 校友卡与班级召集海报均在本机绘制 PNG，支持预览、下载、长按保存与兼容浏览器的系统分享。校友卡包含公开姓名、届别、班级、大学/理想大学、寄语与学校标识；班级海报包含真实有效报到人数。使用字段白名单绘制，不截取成功页，不包括电话、微信、邮箱、编辑码和删除码。
- `/class?graduation_year=2018&class_name=高三1班` 公开显示同班名单、真实人数和分页。“我也是这个班的”保留来源参数，登记表预填届别和班级并允许修改；未来届别预选在读身份。
- 链接和海报二维码包含 `source`、`campaign`、随机 `share_id`。个人海报回到公开卡片；班级海报回到班级名单。当前使用 `alumni_card` / `class_invite` 来源和 `reunion` 活动标识，活动链接也可使用其他合法英文标识。
- 首页和领卡页使用真实人数；无真实登记数时不展示人数背书。班级覆盖率需要可触达总人数，目前仅展示有效报到人数，不猜测覆盖率。

## 新接口与迁移

| 方法 | 路径（`/api/v1` 前缀） | 说明 |
| --- | --- | --- |
| POST | `/alumni/claim` | 免账号领卡；基础登记字段 + 可选 `attribution`，返回 `id/edit_code` |
| POST | `/growth/events` | 接收下述允许的客户端事件；限流、同源限制和长度校验 |
| GET | `/admin/growth` | 管理员查看 UV 与转化率；支持 `days=1..90`（默认 30）、`source/campaign/graduation_year/class_name` 精确过滤 |

旧 `/alumni`、`/auth/register` 账号接口继续兼容；新浏览器领卡流程使用 `/alumni/claim`。未改变社区发帖和上传现有登录要求。

新增 `growth_event` 表及 `alumni.phone_public/wechat_public` 字段；启动检查包含新结构。**备份后执行 `go run ./cmd/migrate`，再发布新二进制/镜像。** 此次没有推送或部署。

领卡与成功事件在同一 MySQL 事务内提交，失败一起回滚；只有成功建档才计成功 UV。档案创建后使公开查询缓存失效，班级人数、通讯录、首页统计随后读取新数据。重复领卡请求使用既有唯一 `CreateKey` 拒绝重复写入。若领卡已提交但响应丢失，重复提交会返回 409，无法重新返回明文编辑码；找回能力属于后续范围。

## 事件、隐私与口径

客户端只可提交 `registration_view/start/failure`、`share_click`、`poster_view/save`、`share_visit`、`edit_code_copy`。`registration_success` 只能由领卡服务端写入，不允许客户端伪造。事件名对应实际完整字符串，如 `registration_view`、`registration_start`、`poster_save`。

浏览器随机标识保留 90 天；分享来源保留在当前会话内，最长 24 小时，以最近有效分享为准。不能使用存储时使用内存标识；不会因此阻止领卡。服务端只存随机标识的 SHA-256 哈希及受限来源、活动、分享 ID、届别、班级，不存姓名、联系方式、编辑码、密码、请求正文或完整 URL。来源等英文标识限制 48 字节，班级限制 30 字。接口不返回原始事件明细。

事件按 UTC 日期、事件、匿名浏览器、分享及来源上下文去重；窗口内 UV 对浏览器哈希去重。复制邀请、系统分享与点击保存海报合并为分享操作 UV，同一浏览器只计一次。`share_visit` 必须携带分享 ID；服务端成功事件携带同一来源上下文，用于计算分享来源领卡 UV。看板计算登记转化率、表单完成率、分享率、分享回流率和分享登记率，无分母显示“—”。

点击、发起下载或唤起分享不保证保存/发送成功；长按保存无法统计。拦截脚本或埋点会导致漏报，跨设备及清理存储会重复计 UV。比率按同一时间窗口内各事件 UV 相除，不代表同一批用户的队列转化，可能超过 100%。仅覆盖本次上线后的免账号领卡链路，不回填历史档案或旧账号接口产生的建档事件。

## 验证与边界

- Go 业务/路由测试：免账号领卡、逐项默认隐私、公开字段、编辑及账号绑定、编辑码失效、重复提交、来源过滤、UV 去重、拒绝伪造成功、管理权限。
- GORM/sqlmock：档案与事件事务回滚、统计 DISTINCT UV 与参数化过滤；miniredis：领卡使通讯录、班级、统计缓存失效。
- 前端语法检查与本地 Edge 演示模式验收，记录于 `docs/verification.md`。演示数据与生产数据隔离。
- 真实 MySQL/Redis、生产 HTTPS 入口、手机实机和微信内保存/分享仍需上线前联调。测试不证明实际用户增长效果。

## P1：扩大传播

- 班级页展示志愿召集人，登录者仅能为本人档案所在班级提交介绍；管理员审核、驳回或撤销，本人可撤回。换班或档案下架后，原班级不再公开展示此召集人，不将召集人等同学校职务或身份认证。
- 按有效档案人数展示 5/10/20/30/50/100 人报到里程碑，达成后可保存班级纪念海报；未达成不生成该里程碑海报。进度明确区别于班级覆盖率。
- 照片详情可生成带原照片、公开说明及二维码的校园记忆卡片；大学页新增届别筛选和分享图，二维码回到对应届别，仅统计实际大学，最多展示前 8 所并注明。
- `/recover` 支持未绑定卡片找回：提交私密核验说明 → 保存申请编号和随机凭证（7 天有效）→ 管理员核实本人及对应申请编号、记录依据后批准 → 凭证一次性领取新编辑码。申请说明本身不能证明身份，不支持仅凭姓名、届别自动重置；运营方需通过已知校友关系完成核验。
- 找回凭证只存哈希，既不进 URL，也不在浏览器持久保存。领取新码事务同时使旧码及其他未完成申请失效，并写审计；已绑定账号的卡片禁止此方式重置。核验失败、过期、重复领取及无权限审核均被拒绝。

P1 新表：`class_organizer`、`card_recovery`。新增 `/class-hub`、`/cohorts/:year/universities`、`/me/organizer`、`/alumni/:id/recovery`、`/recovery/:id/status|complete`、`/admin/organizers|recoveries` 接口。变更后同样需备份并显式迁移。
